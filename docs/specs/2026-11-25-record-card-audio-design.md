# 기록카드 음악 재생 설계 (묶음 9)

> 2026-11-25. `docs/specs/2026-11-16-record-card-design.md`(이하 **설계**)를
> 두 군데 뒤집는다 — 9절 "음악 재생 패키지는 이번엔 안 넣는다", 2절 비목표의
> "실제 소리 재생". 그리고 **6-5절의 "음악이 끝나면 다음 장"도 뒤집는다**(2절).

## 1. 왜

지금 카드 상세의 `재생`/`멈춤`은 **소리가 아니라 포토북이 장을 넘기는 것**만
쥔다. 서버는 곡마다 `musicUrl`을 보내 주는데(연동 가이드 2절) 앱은 그 값을
쓰지 않는다 — `card_music.dart:38`이 "아직 쓰지 않는다"라고 적어 둔 그 필드다.

온보딩 3장이 이미 "함께 달린 데이터로 만든 곡을 받아요"라고 약속하고 있다.
약속한 것이 들리지 않는다.

2026-11-25에 기기에서 확인하다 사용자가 "음악 소리가 왜 안 들려?"로 짚었고,
`just_audio` 도입을 승인했다(CLAUDE.md의 새 패키지 승인 규칙).

## 2. ⚠️ 뒤집는 결정 — 포토북이 저절로 넘어가지 않는다

| 바꾼 것 | 언제 | 뒤집히는 자리 |
|---|---|---|
| **곡이 끝나면 다음 장 → 그 곡을 반복한다.** 장은 **손으로만** 넘긴다 | 2026-11-25 | 설계 6-5의 "음악이 끝나면 자동으로 다음 사진", `card_media_pager.dart:19~34`, `CardMusicTiming` 전체, `MusicStrip.canAdvance` |
| 음악 재생 패키지를 넣는다 | 2026-11-25 | 설계 9절, 2절 비목표 |

사용자가 2026-11-25에 "**음악 재생 버튼 하나만 두고, 페이지 넘어가면 자동으로
그 사진에 맞는 음악이 자동 재생되게. 곡이 끝나면 반복재생**"으로 정했다.

**이것이 자동 넘김을 없앤다.** 곡이 끝나지 않으니 넘길 신호가 없다. 포토북은
사용자가 미는 대로만 넘어가고, 넘어간 장의 곡이 처음부터 자동으로 난다.

따라오는 결과:

- `CardMusicTiming`(기본 30초 · 사진 10초)은 **쓸 데가 없어진다.** 지운다.
- `MusicStrip.canAdvance`도 **없어진다.** "넘어갈 장이 있나"를 묻는 곳이 없다.
- `AppStrings.recordCardMusicReady`("음악이 준비됐어요")도 **없어진다** — 곡이
  있으면 늘 버튼이다.
- `CardMediaPager`에서 `Timer`가 통째로 빠진다. 페이저는 **다시 그리기만** 한다.

## 3. 목표 · 비목표 · 반목표

### 목표

- 포토북의 각 장에서 **그 장의 곡이 실제로 들린다.**
- 장을 넘기면 **그 장의 곡이 처음부터 자동으로** 난다.
- 곡이 끝나면 **그 곡을 반복**한다.
- 곡이 있는 **모든 장**에 재생/멈춤 버튼 하나가 선다 — 마지막 장 포함.
- 카드를 **열면 바로 난다**. 단 다른 앱이 소리를 내고 있으면 접는다(6절).

### 비목표 (지금 안 만든다)

- **백그라운드 재생 · 잠금화면 컨트롤.** `just_audio_background`를 안 넣는다 —
  패키지가 또 늘고 알림 채널·포그라운드 서비스까지 따라온다.
- **진행바 · 탐색(seek) · 볼륨 조절.** 진행바는 2026-11-17에 사용자가 기기에서
  보고 작은 흰 점으로 바꾼 결정이다(설계 6-5 변경 기록). 되살리지 않는다.
- **다음 장 곡 미리 받기(gapless).** 장 사이 끊김이 거슬리는지 **들어 보고**
  정한다.
- **장마다 멈춘 자리 기억하기.** 되돌아온 장은 처음부터 난다.
- **곡 길이 표시.** 서버가 길이를 주지 않는다.
- **iOS.** 안드로이드 우선이다(CLAUDE.md). `just_audio`는 iOS에서
  `AVAudioSession` 설정이 따로 필요한데, iOS 전환 때 같이 본다.

### 반목표 (이것이 되면 실패다)

- **폴링 때문에 듣던 곡이 끊기는 것.** 만드는 중인 카드는 상세를 1분마다 다시
  읽고, **서명 주소는 읽을 때마다 달라진다.** 주소를 그대로 비교하면 1분마다
  소리가 끊긴다. → 7-1절
- **상세를 떠났는데 소리가 계속 나는 것.**
- **만료된 주소로 끝나지 않는 재시도 고리.** 사진에서 이미 겪은 함정이다
  (`card_media_pager.dart:265` — 한 번만 다시 받는다).
- **듣고 있던 남의 소리를 끊는 것.**
- **음악이 안 되면 카드를 못 보는 것.** 설계 2절 반목표 그대로다. 곡이 없거나
  실패해도 글과 사진은 그대로 서고, 손으로 넘기는 것은 그대로 된다.

## 4. 제약

### 계약 (연동 가이드)

- 곡은 **장마다 하나**다. 기본곡 1 + 사진마다 1 (2절).
- 곡 상태는 셋: `GENERATING` · `COMPLETED` · `FAILED`. 곡마다 따로 온다.
- **조회용 주소는 1시간 뒤 만료된다**(7절). 만료되면 403이고, 상세(8-1)를 다시
  불러 새 주소를 받아야 한다.
- 완료를 알리는 **푸시도 SSE도 없다**(7절). 만드는 동안 상세를 다시 읽는다.

### 프로젝트 규칙 (CLAUDE.md)

- 아이콘은 **Lucide만**. 색·치수·타이포·문자열은 전부 토큰.
- `StateProvider` / `StateNotifierProvider` 금지. Riverpod 3, 수동 provider.
- 화면은 loading / data / error 3분기, empty 상태, 다크·라이트 둘 다.
- UI 텍스트는 한국어.
- **한 PR 파일 20개 / 500줄 초과 금지.**
- `domain/`은 순수 Dart만 — **오디오 패키지를 `domain/`에 들이지 않는다.**

### 보안

- **서명된 조회 주소를 로그에 남기지 않는다.** 있고 없고만 적는다. 오류를 적을
  때도 주소를 그대로 흘리지 않는다.

## 5. 어떻게 만드나 — 두 가지를 놓고 A를 골랐다

| | A. **장이 주인** (고름) | B. 재생목록이 주인 |
|---|---|---|
| 누가 순서를 쥐나 | 포토북(사람이 민다) | `just_audio` 재생목록 |
| 장이 바뀌면 | 그 장의 주소를 물리고 튼다 | 플레이어 곡 번호를 옮긴다 |
| 반복 | 그 곡 하나를 반복 | 목록을 돈다 |

**B를 버린 이유 세 가지.** 전부 이 앱의 실제 상태에서 나온다.

1. **곡이 장마다 따로 완성된다.** 기본곡은 됐는데 사진곡은 아직인 구간이 실제로
   있다(2026-11-25 기기 확인). 완성된 곡만 목록에 넣으면 **곡 번호와 장 번호가
   어긋나고**, 빈자리를 채우려면 침묵 트랙을 만들어야 한다.
2. **상세를 1분마다 다시 읽는다.** 카드 객체가 바뀔 때마다 목록을 다시 세우면
   **1분마다 재생이 끊긴다** — 반목표다.
3. **주소가 1시간이면 만료된다.** A는 403 난 장 하나만 다시 받으면 되지만, B는
   목록 전체를 다시 세우는 일이 된다.

게다가 **반복재생으로 정한 뒤로 B의 장점이 없어졌다.** 목록을 미리 받아 두는
이득은 "다음 곡으로 매끄럽게 넘어가는 것"인데, 이제 다음 곡으로 넘어가지 않는다.

## 6. 어떻게 도나

### 6-1. 누가 무엇을 쥐나

| | 쥐는 것 | 지금 | 바뀐 뒤 |
|---|---|---|---|
| `_CardDetailPageState` | `_playing` · `_page` | 그대로 | **플레이어를 모는 유일한 곳** |
| `CardMediaPager` | `PageController` | `Timer`로 넘긴다 | **`Timer`가 빠진다.** 그리고 탭을 받는다 |
| `MusicStrip` | 음악 한 줄 | `canAdvance`로 버튼을 가린다 | **가리지 않는다.** 인자도 뺀다 |
| `cardAudioProvider` | — | 없다 | **`AudioPlayer`를 들고 있다** |

**상세 화면이 플레이어를 모는 유일한 곳이다.** `_page`·`_playing`·`card`를 다
들고 있다. 두 군데서 몰면 줄은 `재생`인데 소리는 나는 어긋남이 생긴다 —
`card_media_pager.dart:58`이 `playing`을 바깥이 드는 이유로 적어 둔 것과 같다.

`CardMediaPager`와 `MusicStrip`은 **오디오를 전혀 모른다.**

### 6-2. 한 장이 서는 동안

```
장이 바뀌었다 / 카드를 열었다 / 곡 상태가 바뀌었다
  │
  ├─ 이 장의 곡이 COMPLETED이고 주소가 있나?
  │    │
  │    ├─ 아니오 (만드는 중·실패·주소 없음)
  │    │      → 소리 없이 선다. 줄은 지금처럼 상태 글자를 보여 준다
  │    │
  │    └─ 예 → 7-1의 신원이 "지금 물려 있는 곡"과 같나?
  │             ├─ 같다   → 아무것도 하지 않는다 (폴링이 돌아도 안 끊긴다)
  │             └─ 다르다 → 물리고, `playing`이면 처음부터 튼다
  │                          · 곡이 끝나면 → 그 곡을 **반복**
  │                          · 403/로드 실패 → 7-3
  │
  └─ 손으로 밀면 위를 처음부터 다시 한다
```

**장은 저절로 넘어가지 않는다.**

### 6-3. 멈추고 버리는 자리

| 언제 | 무엇을 하나 |
|---|---|
| `멈춤`을 누르거나 사진을 탭했다 | `pause()`. 다시 누르면 **멈춘 자리에서 이어 듣는다** |
| 장을 넘겼다 | 그 장의 곡을 **처음부터**. 앞 장의 자리는 기억하지 않는다 |
| **전체 화면이 덮였다** (수정 화면) | 멈추고 `onPlayingChanged(false)`. 돌아와도 **저절로 안 튼다** |
| `⋮` 메뉴 · 삭제 확인 시트 | **계속 난다.** 잠깐 열었다 닫는 것이다 |
| 상세를 떠났다 | `dispose()` |
| 앱이 배경으로 갔다 | 멈추고 `onPlayingChanged(false)`. 돌아와도 **저절로 안 튼다** |

⚠️ **수정 화면으로 가도 상세는 `dispose`되지 않는다** — 라우트를 그 위에 쌓을
뿐이라 상세 위젯은 살아 있다. 그냥 두면 수정하는 내내 소리가 난다(반목표).
**"상세가 최상단 전체 화면 라우트인가"를 보고 멈춘다.** 시트는 라우트지만
전체 화면이 아니라 걸리지 않는다.

## 7. 까다로운 세 자리

### 7-1. ⚠️ 같은 곡인지 어떻게 아나 — 주소로 알 수 없다

**서명 주소는 같은 파일이어도 읽을 때마다 달라진다.** 만드는 중인 카드는 상세를
1분마다 다시 읽으므로, 주소 문자열을 그대로 비교하면 **1분마다 플레이어를 다시
물어 소리가 끊긴다.** 반목표다.

이 레포는 사진에서 같은 함정을 이미 겪었다 —
`ProfilePhotoImage.cacheKeyOf`(`profile_photo_image.dart:59`)가 **`?` 앞만 떼어**
캐시 키로 쓴다. "서명·만료 파라미터를 뗀 자리. 같은 사진이면 이 값이 같다."

같은 방법을 쓴다. **곡의 신원 = `장 번호` + `주소의 ? 앞` + `상태`.**

- 폴링이 같은 곡을 다시 줘도 셋이 같아 다시 물지 않는다.
- 다시 만들기를 걸면 상태가 `COMPLETED → GENERATING → COMPLETED`로 지나가므로,
  서버가 **같은 오브젝트 키를 덮어써도** 상태가 바뀌는 길에 다시 문다.
- 주소 경로까지 매번 달라지는 것으로 밝혀지면 이 규칙이 무너진다. **기기에서
  확인한다**(9절).

### 7-2. 그 장에 서 있는 동안 곡이 완성되면

만드는 중인 장을 보고 있으면 폴링이 바로 그 일을 한다. 6-2의 조건이 "장이
바뀌었을 때"가 아니라 **"신원이 달라졌을 때"**인 이유다 — `GENERATING`에서
`COMPLETED`로 바뀌면 신원이 달라지므로 **그 자리에서 바로 난다.** 장을 다시
밀 필요가 없다.

### 7-3. 주소가 만료됐을 때 (403)

안드로이드에서 올라오는 것은 ExoPlayer 오류라 **HTTP 상태를 믿고 가를 수
없다.** 그래서 **로드 실패를 가르지 않는다** — 어떤 실패든 "만료일 수 있다"로
보고 `cardDetailProvider(cardId)`를 무효화해 새 주소를 받는다.

**그 장에서 한 번만** 한다. 깃발은 **위젯 상태**에 두고 장이 바뀌면 내린다 —
provider에 두면 다음 카드가 물려받는다. 사진이 쓰는 방법과 같다
(`card_media_pager.dart:265`).

두 번째 실패는 **조용히 접는다.** 그 장은 소리 없이 서고 책은 그대로 쓸 수 있다.

## 8. 화면이 어떻게 달라지나

글자와 자리는 그대로다. 눈에 보이는 변화는 **마지막 장에서 문구가 버튼으로
바뀌는 것** 하나다.

```
지금 (사진 1장짜리 카드, 사진 장)      바뀐 뒤
  ┌─────────────────────┐              ┌─────────────────────┐
  │        사진          │              │        사진          │
  │       ● ○           │              │       ● ○           │
  │       결승선         │              │       결승선         │
  │  ♪ 음악이 준비됐어요   │              │  ⏸ 멈춤              │
  └─────────────────────┘              └─────────────────────┘
```

**보이지 않는 변화가 더 크다** — 가만히 두면 장이 넘어가던 것이 안 넘어간다.

## 9. 내가 정한 것 (바꿀 것이 있으면 말해 주면 바꾼다)

| 정한 것 | 왜 |
|---|---|
| 플레이어를 **provider가 들고, 상세 화면만 몬다** | 두 군데서 몰면 줄과 소리가 어긋난다. 상세가 필요한 것을 다 들고 있다 |
| 곡의 신원을 **`장 + 주소의 ? 앞 + 상태`**로 본다 | 주소를 그대로 비교하면 1분마다 끊긴다. 사진이 쓰는 방법과 같다 |
| 이어 틀 때 **멈춘 자리에서** 잇는다 | 소리는 타이머와 다르다. 처음부터 다시 나면 누른 사람이 놀란다. *(기존 `_schedule` 규칙은 타이머의 것이었고 그 타이머가 없어진다)* |
| 되돌아온 장은 **처음부터** 난다 | 장마다 자리를 기억하면 들고 있을 것이 늘고, 그만큼 값을 할 만큼 쓰이지 않는다 |
| **로드 실패를 가르지 않는다.** 전부 한 번만 다시 읽는다 | ExoPlayer 오류에서 403을 믿고 가를 수 없다. 따로 확인 요청을 보내면 데이터 계층에 새 호출이 는다 |
| 전화·헤드폰 뽑힘은 **플레이어 기본 동작**에 맡긴다 | `just_audio`가 `audio_session`으로 안드로이드 오디오 포커스를 기본 처리한다. **기기에서 확인한다** |
| `CardMusicTiming`과 `recordCardMusicReady`를 **지운다** | 설 자리가 없어진다. 남겨 두면 다음 사람이 언제 쓰는지 찾다 만다 |
| 곡이 없는 장에는 **버튼을 두지 않는다** | 지금 그대로다. 틀 것이 없는데 `재생`을 세우면 눌러도 아무 일이 없다 |
| **개발자 모드(가짜 저장소)에서는 소리가 안 난다** | 가짜가 `example.invalid` 주소를 준다(`fake_record_card_repository.dart:569`). 샘플 음원 에셋을 넣는 것은 또 승인받을 일이라 안 넣는다. **실제 서버로 확인한다** |

## 10. 아는 거친 자리 (이번에 안 고친다)

- **만드는 중인 장에서는 줄에 버튼이 없다.** 지금도 그렇다.
- **장을 빠르게 밀면** 지나친 장마다 주소를 물렸다 버린다. 들리진 않지만 헛일을
  한다.
- **장 사이에 소리가 끊긴다.** 새 곡을 받느라 그렇다. 거슬리면 미리 받기를
  그때 넣는다.

## 10-1. ⚠️ 실기기에서 확인해야 하는 것 (2026-11-25 기기 확인)

에뮬레이터에서 6-2의 "남의 소리가 나면 자동 재생을 접는다"를 **가리지
못했다.** `AudioManager.isMusicActive()`가 아무도 소리를 내지 않는 상태에서도
참을 돌려준다 — 앱을 죽이고 재생 중인 플레이어가 하나도 없을 때도 그랬다.
그래서 에뮬레이터에서는 자동 재생이 **언제나** 접히고, "열면 바로 난다"가 한
번도 일어나지 않는다.

- 에뮬레이터 잡음으로 보지만 **확정하지 못했다.** 실기기에서 ① 열면 바로
  나는가 ② 남의 음악을 틀어 둔 채 열면 접히는가, 두 가지를 봐야 한다.
- 이 API는 설계상 **"남의" 소리를 가리지 못한다.** 내 앱이 방금 낸 소리도
  똑같이 참이다. 실기기에서도 어긋나면, 갈 곳은 가드를 걷어내거나
  `getActivePlaybackConfigurations()`를 내 uid만 빼고 세는 네이티브 채널이다
  (`audio_session`에는 없다).

나머지 여섯 가지(반복 · 장 안 넘어감 · 장 넘기면 그 곡 · 시트는 계속 남 ·
수정 화면에서 멈춤 · 홈 버튼에서 멈춤)는 에뮬레이터에서 확인했다. "만드는
중인 카드가 그 자리에서 완성된다"는 카드 없는 러닝 기록이 없어 **기기에서는
못 돌렸다** — 테스트만 있다.

## 11. 빌더에게 남긴 것

- `just_audio` **0.10.6**이 `audio_session` · `just_audio_platform_interface` ·
  `just_audio_web` · `rxdart`를 함께 끌고 온다(2026-11-25 `pub add --dry-run`).
  **설치한 판의 API로 확인하고 쓴다** — 이 문서가 적은 메서드 이름을 믿지 말 것.
- 반복재생을 플레이어의 반복 모드로 걸지, 끝 신호를 받아 다시 틀지는 빌더가
  정한다.
- "다른 앱이 소리를 내고 있나"를 어떻게 보는지(`audio_session`의 포커스 요청
  결과 등)는 빌더가 정한다. **못 얻으면 자동 재생만 접고 버튼은 세운다.**
- "상세가 최상단 전체 화면 라우트인가"를 어떻게 보는지(`ModalRoute.isCurrent`,
  `RouteObserver` 등)는 빌더가 정한다.
- 테스트에서 진짜 소리를 내지 않는다. 플레이어를 **인터페이스로 가리고** 가짜를
  끼운다 — 어디에 선을 긋는지는 빌더가 정한다.
- 안드로이드 설정(`INTERNET`은 이미 있다) 외에 더 필요한 것이 있으면 빌더가
  찾아 적는다.
