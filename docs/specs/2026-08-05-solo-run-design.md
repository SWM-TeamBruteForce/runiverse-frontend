# 홈 화면과 1인 러닝 설계

2026-08-05 · 대상 화면 S05 · S13 파생 · S15

이 문서는 **무엇을 왜 그렇게 정했는지**만 적는다.
GPS가 앱 안에서 실제로 어떻게 동작하는지는 협업 문서(`Runiverse_러닝_협업문서.md`)에 있다.

---

## 1. 범위

홈 화면의 기본 상태와, 매칭 없이 혼자 달리는 세션 하나.

**넣는 것**

- 홈 S05 상태 1 — 히어로 + 버튼 2개 + 카드 스택
- 출발 준비 → 3·2·1 → 러닝 진행 → 요약
- 실시간 페이스 · 시간 · 거리 (GPS로 계산)
- 일시정지 · 재개 · 종료

**빼는 것**

| 뺀 것 | 이유 |
|---|---|
| 홈 상태 2~4 (대기 · 확정 · 실패) | 매칭 기능이 없다 |
| 지도 | 지도 패키지와 API 키 배관이 통째로 따라온다 |
| 좌표 보정 | 3절 참고. 나중에 넣는다 |
| 백그라운드 추적 | 포그라운드 서비스 · 알림 채널 · 제조사별 배터리 최적화까지 얹혀 있다 |
| 컬러 리빌 (S14) | 색 생성 규칙을 먼저 정해야 한다 |
| 기록 저장 | 저장소가 없다. 요약 화면을 나가면 사라진다 |
| 케이던스 · 칼로리 | 5절 참고. 자리만 두고 `--`로 둔다 |
| 음성 코치 | 정본에 있으나 후순위 |

## 2. 화면 흐름

```
홈 (S05 상태1)
 │
 ├─ [지금 매칭하기]  → "준비 중" 스낵바
 │
 └─ [혼자 달리기]
      │
      ▼
   권한 확인 ──거부──► 설정 안내 시트 ──► 홈
      │ 허용
      ▼
   출발 준비  ← GPS 첫 신호를 잡을 때까지 시작 버튼 잠금
      │ [시작]
      ▼
    3 · 2 · 1   ← 되돌아갈 수 없는 구간
      │
      ▼
   러닝 진행 ◄──┐
      │ [중지]  │ [계속 달리기]
      ▼        │
   중지 시트 ───┘
      │ 길게 눌러 종료 (2초)
      ▼
    요약 ──► 홈
```

### 2-1. 왜 출발 준비 화면을 두는가

정본 S11의 컴포넌트 리스트에 이렇게 적혀 있다.

> GPS 인디케이터: 최우선(러닝 실패 예방)

GPS는 앱을 켜자마자 위치를 알지 못한다. 위성을 잡는 데 실내에서는 수십 초가 걸리고,
그 전에 출발하면 **초반 거리가 통째로 빠진다.** 사용자는 자기가 뛴 만큼 기록이 안 나온
이유를 알 수 없다.

그래서 첫 신호를 받기 전에는 시작 버튼을 잠그고, 잠긴 이유를 글로 보여준다.
색만으로 알리지 않는다 (정본 C9 — 상태는 색 단독 금지).

### 2-2. 3·2·1 구간에는 뒤로가기가 없다

정본 S11이 그렇게 정했다(취소 불가 구간). 1인 러닝도 같게 둔다.
카운트다운 도중에 빠져나갈 수 있으면 "시작됐는가"의 판정이 두 곳으로 갈린다.

## 3. 좌표를 보정하지 않는다 `[알려진 한계]`

**제자리에 서 있어도 거리가 늘어난다.**

GPS 좌표는 가만히 있어도 몇 미터씩 흔들린다. 받은 좌표를 그대로 이어 붙이면
그 흔들림이 전부 거리가 된다. 신호가 나쁜 실내에서는 서 있는 채로 분당 수십 미터가 쌓인다.

이번에는 보정을 넣지 않기로 했다. 그래서 **초기 기록은 실제보다 길게 나온다.**
이건 버그가 아니라 알고 남겨둔 상태다.

나중에 넣을 때 한 곳만 고치면 되도록, 좌표가 지나가는 길을 하나로 모아둔다.

```
LocationRepository.watchPosition()  ──►  RunSessionController._onPoint()  ──►  누적
                                              ▲
                                    보정은 여기에 들어간다
```

들어갈 규칙 셋은 이렇다. **값은 실기기에서 정해야 한다.**

| 버릴 점 | 대략의 기준 | 막으려는 것 |
|---|---|---|
| 정확도가 나쁜 점 | `accuracy`가 큰 값 | 위치가 아니라 추정치 |
| 직전과 너무 가까운 점 | 수 미터 미만 | 제자리 표류 |
| 물리적으로 불가능한 점프 | 사람이 낼 수 없는 속도 | 터널 · 건물 반사 |

## 4. 레이어

```
features/session/
  domain/                          순수 Dart. 패키지를 모른다
    geo_point.dart                 위도 · 경도 · 시각 · 정확도
    run_metrics.dart               거리 · 경과시간 · 현재페이스 · 평균페이스
    run_session_state.dart         sealed — 준비 / 진행 / 일시정지 / 종료
    pace_calculator.dart           거리 + 시간 → 페이스
    location_repository.dart       인터페이스

  data/
    geolocator_location_repository.dart
    fake_location_repository.dart  좌표를 손으로 먹인다

  presentation/
    run_session_provider.dart
    run_prepare_page.dart
    run_session_page.dart
    run_summary_page.dart
```

### 4-1. `domain/`이 geolocator를 모르게 둔다

geolocator가 주는 `Position`을 화면까지 들고 가지 않는다. 받는 즉시 `GeoPoint`로 옮긴다.

이유는 둘이다.

- **테스트.** 거리·페이스 계산을 실기기 없이 돌릴 수 있다. `GeoPoint` 목록을 손으로 만들면 된다
- **교체.** 패키지를 바꿔도 `data/` 파일 하나만 다시 쓴다

인증에서 `AuthRepository` 하나에 `FakeAuthRepository`를 끼운 것과 같은 구조다.

### 4-2. 세션 상태는 `keepAlive`다

`implementation-notes.md` §5-1에 적힌 함정이다. **숨은 탭의 provider는 실제로 dispose된다.**
러닝 중에 다른 화면이 위로 올라오면 상태가 통째로 사라진다.

그리고 `ref.onDispose`에서 위치 구독을 반드시 끊는다. 안 끊으면 러닝이 끝나도
GPS가 계속 돌아 배터리를 먹는다.

### 4-3. 화면은 필요한 값만 본다

러닝 화면은 **초당 여러 번** 갱신된다. 상태 전체를 `watch`하면 그때마다 화면 전체가 다시 그려진다.
숫자 한 칸은 자기 숫자만 `select`한다.

## 5. 케이던스와 칼로리는 자리만 둔다

정본 S13의 2×2 그리드는 시간 · 거리 · 케이던스 · 칼로리 넷이다.
레이아웃은 그대로 두되 뒤의 둘은 `--`로 표시한다.

| 지표 | 필요한 것 | 지금 상태 |
|---|---|---|
| 케이던스 | 가속도계 센서 · 걸음 검출 | 센서를 안 읽는다 |
| 칼로리 | 사용자 체중 | 프로필에 체중 항목이 없다 |

지어낸 값을 넣지 않는다. 러닝 기록은 사용자가 믿고 보는 숫자다.
`--`는 "아직 없다"를 정직하게 말한다.

## 6. 홈 버튼의 위계

정본 S05 상태 1에는 `[지금 매칭하기]` 하나뿐이다. 거기에 `[혼자 달리기]`를 더한다.

- `지금 매칭하기` — primary · 56px · **누르면 "준비 중" 스낵바**
- `혼자 달리기` — secondary · 그 아래

지금 동작하는 쪽이 뒤에 있는 셈이라 어색하다. 그래도 이렇게 두는 이유는,
**이 앱의 정체성이 함께 달리는 것**이고 매칭이 붙는 순간 위계를 다시 뒤집는 일이 없기 때문이다.

카카오·애플 로그인 버튼을 자리만 잡아둔 것과 같은 판단이다 (`implementation-notes.md` §9-2).

## 7. 패키지 두 개

| 패키지 | 대안 | 고른 이유 |
|---|---|---|
| `geolocator` | `location` | 권한 요청 · 설정 앱 열기 · 거리 계산이 한 패키지에 있다. `location`은 `permission_handler`를 따로 붙여야 한다 |
| `wakelock_plus` | 없음 | Flutter에 화면을 켜 두는 내장 수단이 없다 |

`wakelock_plus`는 "포그라운드만 추적한다"는 결정의 필연적 결과다.
화면이 꺼지면 추적이 멈추므로, 달리는 동안에는 화면을 켜 둬야 한다.
러닝을 끝내면 반드시 해제한다 — 안 하면 앱을 나가도 화면이 안 꺼진다.

`AndroidManifest.xml`에 `ACCESS_FINE_LOCATION` · `ACCESS_COARSE_LOCATION`을 선언한다.

## 8. 테스트

CLAUDE.md가 정한 세 갈래 중 둘에 해당한다.

**순수 계산**

- 두 좌표 사이의 거리
- 좌표 목록의 누적 거리
- 거리 + 시간 → 페이스 환산 (0으로 나누기 포함)
- 페이스 표기 — `5'32"` 형식

**상태 전이**

- `준비 → 진행 → 일시정지 → 진행 → 종료`
- 일시정지 중에는 경과 시간이 늘지 않는다
- 일시정지 중에 들어온 좌표는 거리에 더하지 않는다
- 종료하면 위치 구독이 끊긴다

시간이 걸리는 판정은 **시계를 주입해서** 확인한다. 인증의 5분 만료를 확인한 방법과 같다.
실제로 5분을 기다리지 않는다.

## 9. 서버에 필요한 것

지금은 없어도 굴러가지만, 기록을 남기려면 필요하다. 협업 문서에 정리했다.

- 러닝 기록 저장 — 거리 · 시간 · 페이스 · 좌표 목록
- 기록 목록 조회 (기록 탭 S21)
- 좌표를 서버에 보낼 것인가 — **보낸다면 개인정보다.** 정책을 먼저 정해야 한다
