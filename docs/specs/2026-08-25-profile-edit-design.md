# 프로필 조회·편집 설계

2026-08-25 · 대상 화면 S22 · S22.1

이 문서는 **무엇을 왜 그렇게 정했는지**만 적는다.

---

## 1. 화면마다 조회를 나눈다 `[2026-08-25 백엔드 협의]`

| 화면 | 조회 API | 상태 |
|---|---|---|
| 프로필 홈 (S22) | `GET /api/v1/users/{userId}` (37번) | **미배포** — 500 |
| 프로필 편집 (S22.1) | `GET /api/v1/users/me/profile` | **명세·배포 전** |

### 왜 나누나

**두 화면이 필요한 값이 다르다.**

홈은 남에게 보이는 것을 그린다 — 닉네임·소개글·사진·친구 수. 타인 프로필과 같은
화면을 쓰므로 경로에 `userId`가 들어가야 한다.

편집은 **내가 고칠 수 있는 것**을 그린다 — 소개글·생년월일·성별·키·몸무게.
이 값들은 남에게 보이지 않아 37번에 실릴 이유가 없고, 실제로 실려 있지도 않다.

### ⚠️ 이것이 신체 정보 문제를 푼다

지금 편집 화면은 생년월일·키·몸무게를 `—`로 둔다. **읽어올 API가 없어서다** —
36번은 `userId`·`nickname`·`isOnboarded`뿐이고 37번에도 없다. 온보딩에서 보내기만
하고 되읽을 길이 없었다.

`GET /users/me/profile`이 붙으면 그 자리가 채워진다.

---

## 2. 아직 정해지지 않은 것

**응답 형식이 확정되지 않았다.** 노션 4.5차 명세서에 아직 GET 항목이 없다.

`PATCH /users/me/profile`(51번)과 짝이므로 같은 필드일 것으로 **짐작**하지만,
확정 전까지 앱은 이 API를 부르지 않는다.

```json
// 짐작이며 확정된 명세가 아니다
{
  "introduction": "즐겁게 달려요",
  "gender": "MALE",
  "birthday": "1998-12-16",
  "weightKg": 70.5,
  "heightCm": 175
}
```

확인이 필요한 것 둘.

- **온보딩 전 사용자**에게 무엇을 주는가 — 409인가, 값이 비어 있는가
- **평균 페이스**(`averagePaceSecondsPerKm`)가 실리는가 — 정본 S22.1에는 없지만
  기능정의서(`SETTING-PERSONAL-001`)는 조회 전용으로 표시하라고 적었다

---

## 3. 지금은 이렇게 돈다 `[임시]`

GET이 붙기 전까지의 상태다.

```
프로필 홈
  GET /users/{userId}  ─ 성공 ─→ 화면 + 기기에 저장
                       └ 실패 ─→ 저장해 둔 값으로 그림 (지금 이 경로)

프로필 편집
  조회하지 않는다. 홈이 받아둔 값을 읽는다.
  신체 정보는 `—`. 바꾼 값만 앱을 켜 둔 동안 메모리에 남는다.

편집에서 나오면
  홈이 GET /users/{userId} 다시 호출 → 저장값 갱신
```

`ProfileBody`(메모리 보관)는 **이 임시 상태를 위해서만 있다.** GET이 붙으면
편집 화면이 서버에서 직접 읽으므로 없어진다.

---

## 4. GET이 붙으면 할 일

1. `ProfileRepository.fetchMyProfile()` 추가 — 소개글·성별·생일·키·몸무게
2. 편집 화면 `initState`에서 호출. 홈이 받아둔 값 대신 이 값을 쓴다
3. **`ProfileBody`와 `profileBodyProvider`를 지운다** — 서버가 진실을 갖게 된다
4. 저장 성공 후 편집 화면이 스스로 다시 읽을지, 홈으로 나갈 때 갱신할지 정한다

⚠️ **4번은 지금 방식(홈이 갱신)으로 두는 편이 낫다.** 편집 화면이 저장 직후 다시
읽으면 왕복이 한 번 더 생기는데, 화면을 나가는 순간 어차피 홈이 받아온다.

---

## 5. 사진이 안 보이는 것은 별개 문제

`GET /users/{userId}/profile-image`(49번)는 **잘 동작한다.** 200으로 주소를 준다.

그런데 아바타는 요약(37번)이 준 주소만 그린다. 37번이 500이라 주소가 없고,
49번이 받아온 주소는 `ProfileImageController`에 담긴 채 아무도 읽지 않는다.

```
49번 200 → ProfileImageController.url  ✗ 화면이 안 봄
37번 500 → 요약에 주소 없음            → 기본 아이콘
```

이렇게 만든 이유는 `fetchUrl()`이 **저장소의 `userId`**를 쓰기 때문이다 —
타인 프로필을 열어도 내 사진이 나온다. 주소는 "누구 것인지 아는 쪽"이 내려줘야 한다.

**37번이 배포되면 저절로 해결된다.** 그전까지 급하면 *요약이 실패했을 때만*
49번 결과로 보충하는 길이 있다(경로에 `userId`가 들어가 타인 프로필에서도 안전하다).
아직 넣지 않았다.
