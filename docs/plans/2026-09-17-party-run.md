# 매칭 후 원격 동반 러닝 — 작업 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 매칭된 방으로 같은 시각에 각자 달리면서, 파티원의 진행률·격차·콤보를 화면에서 보고, 끝난 뒤 파티원과 기록을 비교한다.

**Architecture:** 새 인프라를 만들지 않는다. 솔로 러닝의 WebSocket 채널(`WsClient` → `WsRunningChannel`)과 `PartyBoard`·`partyProvider`가 이미 `RUNNING_PROGRESS_UPDATED`·`RUNNING_COMBO_UPDATED`를 받아 쌓고 있고, 대기실 → 카운트다운 → `openMatched(runningRoomId)` → 러닝 화면 전환도 되어 있다. **빈 곳을 메우고, 파티원 비교 화면을 정본(Figma S13 3/3)대로 다시 그리고, 두 기기로 끝까지 검증한다.**

**Tech Stack:** Flutter 3.44 (fvm) · Riverpod 3 · go_router 17 · `web_socket_channel` 3 · `geolocator` 14 · `sqflite`

**정본:** Figma `Ds2URinGrgXo43wC5OFQ8x` 노드 `4-24` (S11 출발 대기실 `43:46` · S11 카운트다운 `43:113` · S13 3/3 파티원 비교 `45:110`) · `와이어프레임_최종.md` S11 · S13 · S16 · S16.5 · 연동 가이드 5-1~6-2

## 2. 서버 계약 요약 (백엔드 소스 대조, 2026-09-17)

명세 정본: 노션 WEBSOCKET 명세서 › 메시지 › `RUNNING_PROGRESS_UPDATED`(No.7, BE 개발완료·FE 개발전) · `RUNNING_COMBO_UPDATED`. 아래는 소스와 대조해 확인한 내용이며 두 페이지의 필드와 규칙이 소스와 일치한다.

- 봉투 `{"event","data"}`. `RUNNING_STARTED`·`RUNNING_FINISHED`의 `data`는 **`{}`** — 명세의 스냅샷은 미구현. `RUNNING_PAUSE/RESUME` 없음(`paused`는 항상 false).
- `RUNNING_PROGRESS_UPDATED`: **참가자 한 명씩**, 배치마다(≈10초), 보낸 사람 제외. `userId · distanceMeters · targetDistanceMeters? · currentPaceSecondsPerKm? · paused`. 이름·사진·격차·비율 없음.
- `RUNNING_COMBO_UPDATED`: `peers[]{userId, gapMeters(+면 상대가 앞), comboCount, maxComboCount}`. **전체 상태**이고 빈 배열이 곧 콤보 해제. 콤보는 **쌍** 단위, 누적 거리 차 30m 이내, 19초 지나면 제외, 10초 tick.
- 끊김 통지 없음 — 상대 진행이 멈추고 19초 뒤 콤보에서 빠질 뿐이다.
- `/results`: `players[]{userId, nickname, profileImageUrl, status, isMe, isDeleted, totalDistance/Duration/Calories, averagePace, averageCadence, elevationGain}` — **파티원이 이미 들어 있다.** `/split-results`: 10m 구간마다 `players[]{userId, durationSeconds, averagePaceSecondsPerKm, …}` — **파티원 구간도 이미 온다.** 앱 DTO가 본인 것만 골라내고 버리는 중.
- 80% 미만 + 2인 이상 → 20분 쿨다운. `forced`는 의도 기록일 뿐 판정에 안 쓰인다. 결과 응답에 제재 여부는 없고 `/users/me/status`의 `cooldownUntil`만 남는다.
